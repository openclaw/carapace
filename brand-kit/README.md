# OpenClaw brand kit

Browse and download the OpenClaw and OpenClaw Foundation artwork below.

## Continuing source of truth

The live [Carapace brand kit on upstream `main`](https://github.com/openclaw/carapace/tree/main/brand-kit)
is the continuing source of truth for OpenClaw and OpenClaw Foundation artwork.
At the beginning of every branding task, before selecting, reusing, or creating
assets:

1. Resolve upstream `main` afresh and read this README and the relevant linked
   [identity](../openclaw-brand/references/identity.md) and
   [asset-rights](../openclaw-brand/references/asset-rights.md) guidance from that
   revision, plus any relevant asset-specific notices. A local checkout, installed
   package, website copy, old ZIP, or prior output is not proof of current identity.
   If the live source is unavailable, report the blocker instead of silently
   treating a cached kit as current.
2. Record the check time, resolved commit, selected repository paths, and file
   hashes in the task or change evidence. Download selected assets from that
   commit, not a moving branch URL. Pin each task's inputs for reproducibility;
   do not make one observed revision a permanent branding rule.
3. Use the current appropriate assets in the requested new or revised work,
   preserving proportions, outlined lettering, colors, and transparency. The
   current kit outranks stale local, website, and ZIP variants. Follow the current
   usage and rights guidance, retain required notices and human credit, and
   report missing variants or conflicting guidance rather than inventing marks,
   permissions, or clearspace rules.
4. Keep product UI tokens and component contracts, portrait identity, approved
   subbrand compositions, partner marks, and publication/review approvals
   separate. A new artwork revision does not authorize a global palette change,
   background rebrand, or replacement of unrelated or published work. Explicitly
   requested historical reproductions may retain labeled, pinned historical
   inputs, but still begin with the live check and disclose the difference.
5. Recheck after a long pause or before delivery if the source may have changed,
   and reconcile changes within the requested task. Inspect the final artwork in
   context and keep source evidence with the result. Ship reviewed,
   self-contained or repository-local runtime assets, not mutable-`main`
   production hotlinks or a build/CI network gate. Every future task starts with
   a fresh live check again.

All files have transparent backgrounds. Use dark text on light backgrounds and light or white text on dark backgrounds. SVG lettering is outlined; PNG sizes indicate width in pixels.
